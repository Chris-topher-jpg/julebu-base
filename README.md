# 星河游戏俱乐部管理系统

单俱乐部本地应用。Node.js 24 + 原生 ES Modules + SQLite，浏览器无需构建或在线字体资源。

## 启动

```powershell
node server.mjs
```

打开 http://127.0.0.1:4173/ 。开发时可使用 `node --watch server.mjs`。数据首次启动时写入 `data/club.sqlite`，后续启动会保留。默认仅监听本机。

## 演示账号

| 账号 | 密码 | 职责 |
| --- | --- | --- |
| admin | 123456 | 最高负责人：首页统计、俱乐部配置、成员、考官、售后 |
| service | 123456 | 客服：订单、会话、派单、完单验收 |
| escort | 123456 | 打手：接单、本人订单、本人收益与提现 |

最高负责人可在“成员管理”新增账号、选择职责和支持的游戏。新账号密码至少 8 位。停用账号或更改职责会撤销其现有会话；不能停用自己的管理员账号。页面没有俱乐部切换功能。

## 负责人首页

一级导航为首页、俱乐部配置、成员管理、考官管理、售后管理。客服和打手继续使用各自的工作台，统计接口仅限最高负责人访问。

- 经营总数据展示已完成金额、完成笔数、下单用户人数。快照保存在 SQLite 中，每四小时更新，刷新页面不提前重算，并显示统计截止时间。
- 日经营数据可选单日；订单流水趋势可选起止日期，蓝线显示订单数，绿线显示 GMV，支持逐日明细。日数据、曲线和排名每五分钟刷新。
- 陪玩、下单用户、已完成订单三个榜单可独立按日期、游戏、Tag 和金额/笔数筛选排序，支持分页及关联订单明细。
- 日期按北京时间计算，包含结束日，单次最长 366 天。完成指标按完成时间统计；下单用户按创建时间去重，旧订单缺少客户 ID 时按老板称呼去重。多人订单在俱乐部总额中只计一次，陪玩榜每位成员展示参与订单的全额，不代表个人分成，不能相加作为俱乐部 GMV。
- 页面使用已有示例订单，不复制参考截图中的营业额。旧导入示例缺少完成时间时使用下单时间，真实订单缺少完成时间不纳入日期统计。

## 业务流程

“成员管理”展开为“俱乐部成员管理”和“俱乐部陪玩管理”。全体成员包括陪玩，设为陪玩后自动进入陪玩列表。非陪玩可设置为俱乐部会长（最高负责人）、俱乐部财务、俱乐部客服、俱乐部考官、俱乐部售后或普通成员。角色改变即撤销旧会话，服务端逐项限制数据与操作；三类业务人员会自动出现在对应管理页。

陪玩等级从高到低为明星、魔王、巅峰、金牌，默认分成为 85%、80%、75%、70%，可在“等级分成管理”修改。现有未标注等级的成员和订单迁移为金牌，原订单已锁定分成保持不变。游戏技能与成员等级共同决定接单范围，高等级可接低等级订单，反向不允许；派单、直接接单、确认和开始服务均会校验。分成直接取成员等级，不再叠加旧游戏倍率；多人订单每人的等级比例除以参与人数，向下保留到 0.01%，派单后锁定。等级不额外改变现有商品售价。

支持成员搜索、角色筛选、陪玩技能与状态筛选、分页、批量增加技能、冻结/解冻。冻结后禁止接新单和开始服务，已开始的服务仍可提交完单。取消陪玩身份需先结清订单、余额及提现，取消后保留普通成员身份。降低等级或删除技能不得与待确认、待服务订单冲突。

客服创建订单 → 派单给支持该游戏的在线成员 → 成员确认接单 → 开始服务 → 提交完单说明 → 客服验收 → 分成入账 → 成员申请提现 → 管理员审核 → 待线下打款。

- 打手也可在接单大厅领取匹配游戏的未分配订单。
- 订单有版本检查，同一订单不能被重复接走；同一成员不能同时开始两笔服务。
- 派单校验人数、游戏状态、在线状态与分成总和；分成保留在订单中，后续改成员比例不影响已分配订单。
- 金额以整数分保存，按服务端商品定价；余额支付校验并扣减余额。
- 完单必须验收后才能入账；充值和验收都不能重复入账。
- 提现扣减可提现余额并冻结，驳回返还；押金低于 1,000 元、账号停用或已有待审核申请会拦截。
- 登录使用散列密码与 HttpOnly / SameSite Cookie，会话有效期 8 小时；每次接口请求都重新校验账号与角色。角色和订单归属由服务端决定。

## 当前范围

这是使用演示数据的本地可运行版本。会话页面保留历史示例咨询，支持内部跟进记录；尚未接入微信、站内客户消息网关。提现审核只记录“待线下打款”，不会实际付款。游戏与商品目前保留配置展示。生产部署仍需配置 HTTPS、正式账号和密码管理、备份及真实支付/消息接口。
