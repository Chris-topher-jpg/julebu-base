# 星河游戏俱乐部基础版

第三档交付版本，对应 10,000 元 / 月档位。定价属于销售方案，不是系统向客户收取的服务价格。

## 保留的业务链路

服务大厅选择游戏与服务 -> 注册 / 登录 -> 提交订单 -> 线下付款报备 -> 客服核款 -> 客服派单 -> 陪玩开始服务 -> 提交完成 -> 客户验收。

- 用户：浏览项目、下单、查看本人订单、报备付款、取消未付款订单、验收、发起客服咨询。
- 客服：核对线下到账、分配陪玩、查看订单记录、按状态筛选及搜索、回复咨询。
- 陪玩：仅查看分配给自己的订单、开始服务、提交完成。
- 管理员：新增与编辑游戏、自定义游戏类别和服务类型、配置小时服务与固定套餐、游戏上下架、关联服务及调价、处理订单、创建客服和陪玩账号。
- 所有账号可修改密码。服务计价方式、单价、总价、时长、游戏名称和类别在下单时快照保存，后续调整不影响原订单。
- SQLite 持久化保存订单和流程记录；角色与状态转换由服务端校验。

## 基础版体验优化

- 服务大厅：游戏类别、游戏与关键词筛选、价格与时长排序、服务详情、预约需求填写、下单说明及客服入口。
- 工作台：按角色显示待办数量、待办订单和真实订单动态；不包含营收或经营分析。
- 订单中心：状态标签、搜索、分页、完整详情、五阶段进度和操作确认；用户支持从已结束订单再次下单。
- 核款异常：客服填写原因后退回报备，用户可以补充信息重新提交；仍须人工确认到账才能派单。
- 服务跟进：客服及已分配的陪玩可记录跟进内容，客户可见，已结束的订单不允许继续追加。
- 客服咨询：用户可发起普通或关联本人订单的咨询；客服和管理员共享待回复列表，可回复、结束咨询。用户补充消息会重新进入待回复，双方可查看历史记录。页面每 5 秒检查新回复，可手动刷新；没有推送通知。
- 用户在顶部“客服咨询”或订单详情“咨询此订单”发起消息；客服登录后从左侧“客服咨询”进入待回复列表。咨询消息只在用户与客服/管理员之间可见，不改变订单状态。未登录访客仍使用俱乐部配置的线下联系方式。
- 人员维护：管理员可启停业务账号；停用会清除会话，且不能停用仍有未完成订单的陪玩。
- 已有基础版数据库会在启动时自动补充游戏目录、服务关联和订单快照字段，保留服务、订单及流程记录；同时适配桌面和手机页面。

客户报备付款只会进入“待核款”，只有客服或管理员确认实际到账后才能派单。未接入在线支付；收款信息通过 `CLUB_PAYMENT_CONTACT` 配置。已报备或确认收款的订单不提供直接取消，退款争议需线下处理。

## 游戏与服务配置

1. 管理员进入“游戏与服务 → 游戏目录”，点击“新增游戏”，填写名称和类别。类别可选择现有值，也可直接输入新类别，例如 MOBA、射击竞技、休闲经营。
2. 切换到“服务项目”，点击“新增服务”或“编辑”，选择所属游戏并自定义服务类型（例如语音陪玩、教学陪练、组队开黑）；“通用服务”可用于所有在架游戏。
3. 选择计价方式：**按小时**填写每小时单价，用户下单时自选 1–24 整小时，支持加减、直接输入和快捷时长，实时显示总价；例如 68 元 / 小时，选择 3 小时合计 204 元。**固定套餐**填写套餐所含时长及总价，例如 2 小时 / 128 元，用户购买 1 份的总额就是 128 元，不能单独修改套餐时长。
4. 同一服务类型可同时提供小时服务和固定套餐；通过“复制服务”带入类型、计价方式、游戏和说明，填写新名称和价格后保存为独立服务。切换计价方式时，请重新核对每小时单价或套餐总价。
5. 客户在大厅按游戏类别、游戏、计价方式、服务类型和时长筛选；小时服务可匹配任意 1–24 小时，固定套餐只匹配其所含时长。下单时选择游戏，专属服务只允许选择其关联游戏，区服与预约时间选填。订单详情显示下单时的计价明细；后台修改不会改变已有订单。若填写订单期间服务调价、切换计价方式或更改套餐时长，提交会被拒绝并显示最新报价，保留填写内容，需用户核对后再次确认。
6. 下架游戏会隐藏该游戏及其专属服务，阻止新订单；已有订单仍可正常履约。游戏重新上架后，其在售服务恢复展示。

已有基础版服务默认作为通用服务。历史订单未记录的游戏不会被猜测填入，原需求备注保留。演示环境提供三角洲行动、王者荣耀、无畏契约、和平精英及英雄联盟；正式环境需自行添加游戏。

原基础版服务与历史订单在升级时保留为“固定套餐”，总价与时长保持不变；如需用户自选小时，由管理员将对应服务改为“按小时”并设置单价。升级会自动补充计价字段，不需要删除或重建数据库。总价由服务端根据当前服务配置计算，客户端传入的单价、总额或伪造计价方式不会覆盖服务端价格。

## 已移除

实名认证、考核入驻、等级及会员体系、自动匹配与报名、WebSocket 即时聊天、通知同步、充值余额、提现退款、分账结算、财务分析、经营分析及自定义权限体系。对应旧代码、旧测试和旧文档均从本版本移除，可通过 Git 历史查看。

## 本地预览

需要 Node.js 24 或更新版本，无需安装第三方依赖。

```powershell
npm start
```

打开 http://127.0.0.1:4173/ 。默认仅监听本机。新数据库自动创建于 `data/club-basic.sqlite`，与旧版 `data/club.sqlite` 隔离；此版本不迁移旧业务数据。

## 正式环境

按照 `.env.example` 设置环境变量，使用 `node --env-file=.env server.mjs` 启动。首次启动必须使用独立数据库并提供至少 12 位管理员密码；正式环境不生成演示账号和示例项目。管理员登录后先新增游戏、关联服务、客服及陪玩账号，再开放注册下单。

正式访问入口需配置 HTTPS 反向代理，`CLUB_PUBLIC_ORIGIN` 填写实际来源。服务继续只监听本机，登录 Cookie 带 `Secure`。反向代理应按真实客户端 IP 限流。数据库和凭据不得进入 Git。

停服后备份 SQLite 数据库及同目录的 `-wal`、`-shm` 文件（如存在）；恢复到新的独立路径并用 `CLUB_DATABASE` 指向该路径。上线前需自行完成收款渠道配置和真实业务验收。
