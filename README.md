# 星河游戏俱乐部基础版

第三档交付版本，对应 10,000 元 / 月档位。定价属于销售方案，不是系统向客户收取的服务价格。

## 保留的业务链路

服务大厅选择游戏与服务 -> 注册 / 登录 -> 提交订单 -> 线下付款报备 -> 客服核款 -> 客服派单 -> 陪玩开始服务 -> 提交完成 -> 客户验收。

- 用户：浏览项目、下单、查看本人订单、报备付款、取消未付款订单、验收。
- 客服：核对线下到账、分配陪玩、查看订单记录、按状态筛选及搜索。
- 陪玩：仅查看分配给自己的订单、开始服务、提交完成。
- 管理员：新增与编辑游戏、自定义游戏类别、游戏上下架、关联服务及调价、处理订单、创建客服和陪玩账号。
- 所有账号可修改密码。服务价格、游戏名称和类别在下单时快照保存，后续调整不影响原订单。
- SQLite 持久化保存订单和流程记录；角色与状态转换由服务端校验。

## 基础版体验优化

- 服务大厅：游戏类别、游戏与关键词筛选、价格与时长排序、服务详情、预约需求填写、下单说明及客服入口。
- 工作台：按角色显示待办数量、待办订单和真实订单动态；不包含营收或经营分析。
- 订单中心：状态标签、搜索、分页、完整详情、五阶段进度和操作确认；用户支持从已结束订单再次下单。
- 核款异常：客服填写原因后退回报备，用户可以补充信息重新提交；仍须人工确认到账才能派单。
- 服务跟进：客服及已分配的陪玩可记录跟进内容，客户可见，已结束的订单不允许继续追加。
- 人员维护：管理员可启停业务账号；停用会清除会话，且不能停用仍有未完成订单的陪玩。
- 已有基础版数据库会在启动时自动补充游戏目录、服务关联和订单快照字段，保留服务、订单及流程记录；同时适配桌面和手机页面。

客户报备付款只会进入“待核款”，只有客服或管理员确认实际到账后才能派单。未接入在线支付；收款信息通过 `CLUB_PAYMENT_CONTACT` 配置。已报备或确认收款的订单不提供直接取消，退款争议需线下处理。

## 游戏与服务配置

1. 管理员进入“游戏与服务 → 游戏目录”，点击“新增游戏”，填写名称和类别。类别可选择现有值，也可直接输入新类别，例如 MOBA、射击竞技、休闲经营。
2. 切换到“服务项目”，新增或编辑服务并选择所属游戏；“通用服务”可用于所有在架游戏。
3. 客户在大厅按类别或游戏筛选，在下单表单中选择游戏；专属服务只允许选择其关联游戏，区服与预约时间选填。
4. 下架游戏会隐藏该游戏及其专属服务，阻止新订单；已有订单仍可正常履约。游戏重新上架后，其在售服务恢复展示。

已有基础版服务默认作为通用服务。历史订单未记录的游戏不会被猜测填入，原需求备注保留。演示环境提供三角洲行动、王者荣耀、无畏契约、和平精英及英雄联盟；正式环境需自行添加游戏。

## 本地预览

需要 Node.js 24 或更新版本，无需安装第三方依赖。

```powershell
npm start
```

打开 http://127.0.0.1:4173/ 。默认仅监听本机。新数据库自动创建于 `data/club-basic.sqlite`，与旧版 `data/club.sqlite` 隔离；此版本不迁移旧业务数据。

## 正式环境

按照 `.env.example` 设置环境变量，使用 `node --env-file=.env server.mjs` 启动。首次启动必须使用独立数据库并提供至少 12 位管理员密码；正式环境不生成演示账号和示例项目。管理员登录后先新增游戏、关联服务、客服及陪玩账号，再开放注册下单。

正式访问入口需配置 HTTPS 反向代理，`CLUB_PUBLIC_ORIGIN` 填写实际来源。服务继续只监听本机，登录 Cookie 带 `Secure`。反向代理应按真实客户端 IP 限流。数据库和凭据不得进入 Git。

停服后备份 SQLite 数据库及同目录的 `-wal`、`-shm` 文件（如存在）；恢复到新的独立路径并用 `CLUB_DATABASE` 指向该路径。上线前需自行完成收款渠道配置和真实业务验收。
