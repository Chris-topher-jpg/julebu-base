# 星河游戏俱乐部后台管理链路

## 一条完整链路

```text
用户进入俱乐部用户池
  -> 负责人按用户 ID 加入俱乐部成员
  -> 设置唯一职责（普通成员 / 客服 / 考官 / 售后 / 财务 / 最高负责人）
  -> 如需接单，补充押金、等级、游戏并转为陪玩
  -> 游戏配置与商品定价
  -> 客服接待用户、确认游戏/商品/时长/支付方式
  -> 创建订单
  -> 系统按游戏、在线状态、冻结状态和等级筛选可接成员
  -> 客服邀请与符合条件的陪玩自主报名同步进行
  -> 老板从两类候选中选择，选定前订单持续开放
  -> 陪玩确认接单
  -> 开始服务
  -> 陪玩提交完单说明
  -> 客服或售后验收 / 退回补充服务
  -> 验收通过，按派单时锁定的游戏抽佣比例入账
  -> 陪玩申请提现
  -> 财务审核
  -> 待线下打款
  -> 流水、审计和经营统计留痕
```

## 当前已完成

- 最高负责人拥有首页、俱乐部配置、成员、客服、考官、售后、财务、订单和用户管理。
- 角色权限由服务端校验，角色改变会撤销旧会话；一个成员只能有一种当前职责。
- 用户管理展示用户编号、内部 ID、昵称、账号、联系方式、余额、订单统计、累计消费和俱乐部身份。
- 成员加入改为输入已有用户 ID。加入动作只建立俱乐部成员记录，不创建新的登录账号。
- 成员可设置为陪玩；设为陪玩时填写押金、等级和游戏。等级仅用于接单门槛，抽佣比例在财务管理中按游戏配置。
- 等级门槛为明星、魔王、巅峰、金牌，高等级可以接低等级订单；已派订单锁定当时的游戏抽佣比例。
- 成员、陪玩、客服、考官、售后、用户、财务和订单列表都提供 ID / 昵称或业务字段检索。
- 支持订单版本校验、重复派单拦截、服务冲突拦截、冻结账号、冻结余额、提现冻结和审计记录。
- 经营总数据每四小时快照；日数据、趋势、陪玩排名、用户排名、订单排名支持时间、游戏和 Tag 筛选。
- 售后可创建退款申请，按余额原路或线下人工渠道审核；部分退款累计控制额度，重复审核会被拦截并记录流水。
- 会话保存 SLA 截止时间并标记超时；负责人可下载经营汇总 CSV，并在俱乐部配置中检索操作审计。
- 提现审核完成后进入“待线下打款”，财务登记打款流水号后才进入“已打款”，避免审核状态与实际付款混淆；交易和打款流水号做幂等去重。

## 尚未接入

- 用户来源仍是俱乐部本地用户池，没有接入微信、游戏平台或统一用户中心的真实用户接口。
- 站内会话支持双方发送、独立未读、8 秒轮询与内部跟进；尚未接入微信等外部渠道或自动催办通知。
- 提现会记录“待线下打款”和“已打款”及人工流水号，但不会调用真实支付或银行打款接口。
- 当前“在线支付”只代表站内余额扣款；充值仍依赖人工凭证审核，没有微信/支付宝支付回调、签名校验和自动对账。
- 余额退款通过审核后立即返还；线下退款先进入“待线下退款”，财务登记实际退款流水后才完成，尚未接入微信/支付宝原路退款回调和自动对账。
- 经营统计已支持汇总 CSV 导出；尚未提供定时报表、完整明细导出和异常数据告警。
- 生产环境还需要 HTTPS、正式账号密码策略、管理员二次验证、数据库备份、操作审计查询和更细粒度的数据脱敏。

## 已做的流程优化

### 人员加入

用户先存在用户管理，再由负责人使用用户 ID 加入成员。系统校验用户是否存在、是否已经入会、成员编号是否重复；加入后用户管理显示“已加入”和当前职责。这样可以避免重复创建账号，也能保持用户资料与俱乐部成员职责分离。

### 职责与陪玩准入

职责和陪玩身份分开处理。成员先拥有一种职责，需要接单时再转为陪玩；设为陪玩必须同时补齐押金、等级和至少一个游戏。修改游戏或等级会检查待确认、待服务订单，避免修改后订单无法履约。

### 订单与资金

订单金额只能由服务端根据商品和时长计算；余额支付即时扣减，线下收款会自动建立用户档案。派单时记录每位陪玩的游戏抽佣比例和预计收益，后续配置调整不会影响已派订单。验收通过才入账，提现申请先冻结余额，驳回后返还。

### 管理查询

列表查询优先使用用户 ID，其次使用昵称；订单和财务列表同时支持业务单号、老板、陪玩、游戏、状态等字段。搜索只在当前工作区过滤，不改变服务端权限边界。

## 建议的生产落地顺序

1. 接入真实用户中心，使用不可变外部用户 ID，禁止用昵称作为唯一关联键。
2. 接入支付回调和财务对账，给充值、退款、提现增加幂等号。
3. 接入第三方退款回调、售后工单、客服消息通知和 SLA 自动催办。
4. 增加角色变更审批、关键财务操作二次确认、完整报表导出和异常告警。
5. 增加数据库备份恢复演练、HTTPS、二次验证、限流和生产监控。

## 本轮完善与流程修正

依据全链路文档，已补齐普通成员个人能力、双向站内消息、游戏商品维护和真实财务总览。订单详情展示阶段、下一步、服务说明和时间线，管理首页提供六类直接处理的待办。

结算统一在验收时执行。部分退款先返还消费余额，若服务尚待验收则继续验收剩余金额；已结算订单退款会同步冲回陪玩收益，收益余额不足时阻止退款并要求先处理冻结提现或结算。提现审核通过仍保持冻结，实际登记打款后结束。老板订单转派后重新进入候选阶段，由老板重新选择，新成员确认接单后才能开始服务。

游戏商品修改校验版本，价格变更保留旧订单快照；已引用配置不能删除。下架停止新订单，不阻断已有订单履约。真实支付、外部消息、银行打款与自动对账仍需配置对应服务。

服务开始前的待接单、待确认、待服务订单均可申请退款。审核期间暂停接单和开服，仍保留成员履约约束；全额退款结束订单，部分退款或驳回恢复申请前阶段，后续收益按扣除退款的金额计算。指定陪玩先校验游戏人数、成员冻结及等级，避免付款后无法派单；同名顾客按本人客户 ID 扣款，商品名称长度不再阻断下单。

老板下单后的候选名单由客服推荐与打手自主报名合并，按真实成员 ID 去重。报名不分配服务成员、不锁定分成；老板选择时再次校验游戏、等级、在线、冻结状态、订单归属和订单人数，且使用订单版本避免重复选择。候选来源和报名时间持久保存；打手只能读取自己的报名，老板只能选择自己订单中的候选人。退款审核期间暂停招募和选择。
