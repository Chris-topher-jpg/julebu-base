# 系统 A（基础版）

需求来源：https://docs.qq.com/doc/DVHFNRFJRSVJBakpq 。2026-10-09 按其中系统 A 清单调整，A 为 A/B/C 最低档；不推断 B、C 的范围或价格。

## 保留范围

| 使用者 | 功能 |
| --- | --- |
| 管理员 | 经营汇总、买家/陪玩排名、日/月退款金额；全部订单、待派/进行中/转单和派单记录；财务概况、充值、退款、流水、提现结算、抽佣；游戏与等级定价、小时和固定套餐；用户与陪玩；考核申请、收费及考官安排；售后退款队列 |
| 客服 | 待派、进行中、待验收订单及尚未回复会话；直接派单、转单、服务进度、用户验收和退款记录；退款申请通知管理员/财务 |
| 陪玩 | 已接订单、待确认/待开始待办、当前服务、可提现余额；本人订单与差评；日/周/月收益、冻结金额、待验收收入、押金 |
| 用户 | 余额、未完成订单、未读会话、点单记录/详情；下单、指定陪玩、充值流水、实名；客服与售后、退款与赔偿记录；未开始余额订单取消、完单确认和评价 |
| 公共首页 | 可售服务、在线空闲陪玩、全部陪玩目录（游戏与离线/空闲/服务中状态）、服务保障 |

## 完整链路

1. 管理员配置游戏、陪玩等级与商品价格，安排成员及接单资格。
2. 用户实名并充值余额，选择小时或套餐提交订单，客服收到提醒。
3. 客服按游戏、等级、在线状态及忙闲情况派单；陪玩确认、开始服务并提交完单说明。
4. 用户验收（客服可协助复核），系统按派单时锁定的比例结算，陪玩申请提现，财务审核并登记打款。
5. 未开始的余额订单可由用户取消并退回余额；其他退款走售后审核，保留退款、收益冲回和流水记录。线下退款必须登记实际打款。
6. 已完成订单可评价一次；1–2 星在对应陪玩的“差评记录”中查看。
7. 用户在订单中申请赔偿，客服/售后也可代为发起；财务或管理员核准后发到账户余额，驳回需填写原因，用户可撤回本人待审申请。赔偿单独留痕、通知和入账，由俱乐部承担；不扣陪玩收益、不冲减订单退款额度、不计入日/月退款金额，也不中断订单履约。赔偿金额按协商结果填写，可超过订单本金，须经财务核准。

## 文档逐项核对（2026-10-10）

| 文档要求 | 当前入口及实现 |
| --- | --- |
| 管理：首页经营数据、用户/陪玩排名、日/月退款 | 管理首页经营数据、排行榜及退款金额，按北京时间统计 |
| 管理：全部/进行中/待派订单、转单和派单记录 | 订单管理子菜单与状态筛选 |
| 管理：财务总览、充值退款、资金流水、提现结算、抽点 | 财务管理各子菜单；赔偿到账同步记录“售后赔偿”流水 |
| 管理：游戏、陪玩等级价格 | 俱乐部配置 → 游戏与商品，按游戏配置等级价格 |
| 管理：成员和陪玩管理 | 成员管理 → 成员、陪玩、职责和账号状态 |
| 管理：考核申请、费用、考官分配 | 入店考核 |
| 管理：售后退款处理队列 | 售后管理，待处理退款优先；下方独立赔偿记录及审核 |
| 客服：待派/进行中/待验收、未联系会话 | 工作台指标、订单工作台；“跟进未联系会话”入口和未联系/待回复筛选 |
| 客服：订单状态、自动分配收益、退款通知 | 全状态订单筛选；验收时自动结算一次；退款通知财务及负责人 |
| 陪玩：已接订单、待办、余额、当前服务 | 打手工作台 |
| 陪玩：各状态订单、差评 | 我的订单及差评记录筛选 |
| 陪玩：日/周/月流水、冻结、待验收、押金 | 我的收益；日/周/月采用北京时间，周一开始，扣除退款冲回；冻结同时包含人工及提现冻结 |
| 用户：余额、进行中/待验收、未读、订单记录 | 个人中心首页及我的点单 |
| 用户：客服/售后对话、退款和赔偿金额 | 消息与售后，退款记录与独立赔偿记录；赔偿显示待审、到账金额、处理时间和说明 |
| 用户：钱包、充值记录、余额明细、实名 | 我的钱包及实名认证；员工切换个人身份也能查看本人充值记录 |
| 首页：单子玩法、在线有空陪玩 | 首页商品与在线空闲陪玩；登录前后使用同一忙闲依据，目录可看全部陪玩状态 |

核对范围仅为链接中的系统 A，不增加 B/C 版范围。外部自动支付仍未接入；赔偿当前发到账户余额，线下退款继续使用已有实际流水登记流程。

## 简化与兼容

- 移除语音大厅/试音、动态广场的页面入口并禁用相关 API。A 版服务不初始化其运行实例。
- 取消陪玩自主报名及买家候选选择，统一客服直接派单；过滤旧招募/语音通知。
- 旧招募订单读取时按 A 版展示，不删除原申请记录；处理时转为客服派单。已分配、履约中、完单及资金记录保持可处理。
- 后台按订单、会话、财务、配置、成员、考核、售后归组，人员职责设置保留在成员管理中。
- 保留旧模块源码用于完整版本领域回归；恢复完整体验须用完整版本保留分支，不能仅切换 HTTP 工厂的 `edition` 参数。
- 当前支付仍为余额扣款和人工充值/退款/提现审核，未接入外部自动支付网关。

## 验证

`npm run build`、`npm test` 检查 A 版及原有领域回归；`tests/system-a.test.mjs` 覆盖版本入口、派单履约提现、旧单兼容、忙闲/转单、取消幂等、退款冲回、评价权限、会话联系状态和退款统计。原基础版通过独立 `build:basic`、`test:basic` 验证，未修改其文件。

安装 Playwright 及其 Chromium 后，运行 `node scripts/system-a-smoke.mjs` 验证桌面/手机页面、角色入口、取消退款和服务评价。也可通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径、`BROWSER_EXECUTABLE` 指定 Chrome 路径。脚本仅使用内存测试库，截图保存到忽略的 `test-results/system-a/`。旧 `dispatch-smoke.mjs` 用于完整版本，请在完整版本保留分支运行。
